# Agent Spec — AI PM Digest

## Overview
A headless ADK agent that runs once each morning. It gathers the last ~24 hours of AI news
aimed at a **PM who builds**, picks the 8–12 items worth their time, explains why each one
matters to a product builder, and emails a short HTML digest (about a 5-minute read) to the
user's Gmail. There is no chat interface: a scheduled job starts the run, which exits once the email is sent.

## Language
`python` (ADK Python, `adk` template, `--prototype`).

## Architecture & Sub-Agents
Plain Python code handles collection and delivery; the LLM only does judgment and writing.

```
launchd (07:00 daily)
  └─ run_digest.py
       1. collect_feeds()      Python: fetch RSS/Atom feeds, keep items < 36h old,
                               drop URLs already sent (seen_urls.json)      → state["feed_items"]
       2. SequentialAgent "digest_pipeline"
            a. scout_agent     LlmAgent + google_search: finds ≤5 major stories
                               from the last 24h that are NOT in feed_items → state["scout_items"]
            b. editor_agent    LlmAgent, output_schema=Digest: dedupes, ranks, picks
                               8–12 items into 4 sections, writes "why it matters"
       3. validate()           Python: every item URL must appear in feed_items or
                               scout_items; unknown URLs are dropped
       4. render_html()        Python template → email body
       5. send_gmail()         Python smtplib → smtp.gmail.com:465, app password
       6. record sent URLs     → seen_urls.json (so items don't repeat tomorrow)
```

**Why the scout is its own agent:** ADK's built-in `google_search` tool can't share an agent
with other tools, and keeping it separate lets the editor work only from saved inputs, never
from its own memory.

### Approaches considered
- **A. Single agent with search + feed tool + send tool.** Fewest files, but the model decides
  when to send email and can cite URLs it invents. Rejected: unsafe and hard to evaluate.
- **B. Python collect → scout + editor agents → Python send (chosen).** Delivery and link
  checking stay deterministic; the LLM does only what it's good at (ranking and writing).
  Easy to evaluate the editor on fixed inputs.
- **C. Adapt `deep-search` wholesale (plan → search → critique loop).** Higher quality ceiling
  but 5–10× the tokens and time per run, and the approval step makes no sense for a daily job.
  Kept as a Future Phase for a weekly "deep dive" edition.

## Digest Sections
1. **Models & lab releases:** new models, pricing and API changes, lab announcements.
2. **Builder tools & launches:** coding agents, frameworks, dev tools, notable launches.
3. **Product & strategy:** AI product teardowns, PM essays, adoption and business moves.
4. **Research worth knowing:** 1–2 papers or ideas in plain language, no math.

Plus a one-paragraph **"If you read one thing"** lead at the top. Empty sections are left out
rather than padded.

Each item: headline · source · 1–2 sentence summary · **"Why it matters for PMs"** (one line).

## Tools & Data Sources
| Component | Purpose | Auth |
|---|---|---|
| `collect_feeds()` (feedparser + httpx) | Pull items from `feeds.yaml` | None (public feeds) |
| `google_search` (ADK built-in) | Scout pass for stories missing from the feeds | Gemini API key |
| Gemini via AI Studio | Scout + editor models | `GOOGLE_API_KEY` in `.env`, entered by the user |
| `send_gmail()` (smtplib, SSL 465) | Deliver the digest | Gmail **app password** in `.env`, entered by the user |

Starter `feeds.yaml` (editable; each feed is checked during build and dead ones are dropped):
OpenAI News, Google AI Blog, Google DeepMind, Anthropic News (via a maintained RSS mirror if there's no official feed),
Meta AI, Hugging Face Blog, Hugging Face Daily Papers, Hacker News (AI stories with ≥100 points),
Simon Willison, Latent Space, Lenny's Newsletter, Product Hunt (AI), The Verge AI, TechCrunch AI.

## Example Use Cases
- **Normal day:** 60 feed items + 3 scout finds → a 10-item digest; each item links to a real
  source; email arrives by 07:05.
- **Big launch day** (e.g., a frontier model release covered by 8 sources) → one item citing the
  primary source (the lab's post), not 8 near-duplicates.
- **Slow day** (weekend, <5 good items) → a shorter digest with a note saying so; never padded
  with stale items.
- **Feeds partly down** → still sends with the remaining sources; the footer lists feeds that failed.

## Constraints & Safety Rules
- **Recipient is fixed** in `.env` (`DIGEST_TO`); the LLM never decides who gets email and never
  has a send tool.
- **No invented links:** after the editor runs, code drops any item whose URL wasn't in
  `feed_items` or `scout_items`.
- **No repeats:** a URL sent in the last 14 days isn't sent again unless the model marks it as a major
  update (a new version or a new announcement).
- **Minimum bar:** fewer than 3 valid items → no email; log a warning instead.
- **Secrets** live only in `.env` (git-ignored), and the user types them in themselves. They're never
  logged or printed.
- **Dry run:** `--dry-run` writes `out/digest-YYYY-MM-DD.html` without sending, for testing.
- Summaries are paraphrased, not copied: at most one short quote per item.

## Scheduling
macOS `launchd` agent at **07:00 local time**. If the Mac was asleep, it runs when it wakes.
Logs go to `logs/`. Moving to Cloud Run with Cloud Scheduler is a Future Phase.

## Success Criteria (evaluation)
Evaluated with `agents-cli eval` on 3–5 saved daily snapshots (fixed `feed_items` fixtures):
- **Link grounding:** 100% of item URLs come from the inputs (checked in code, must pass).
- **Dedup:** the same story never appears twice in one digest (LLM judge ≥ 4/5).
- **PM relevance:** "why it matters" is specific and useful to a PM builder (LLM judge ≥ 4/5
  average).
- **Coverage:** when the fixture contains a major lab model release, it appears in the digest
  (pass/fail).
- **Format:** 8–12 items on a normal day; each has a headline, source, summary and why-it-matters (checked in code).
- **Ops:** a full run finishes in under 3 minutes; the email lands in the Gmail inbox, not spam
  (manual check on first run).

## Assumptions
- Email is sent **from and to your own Gmail address** (both set in `.env`).
- Delivery time **07:00** local, **every day**, weekends included.
- Model: the **latest generally available Gemini Flash** model, confirmed by listing the available models with your
  key before coding (Flash handles curation well and keeps the daily cost near zero).
- A simple `seen_urls.json` file is enough memory across days; no Memory Bank needed.
- No feedback or personalization loop in v1.
