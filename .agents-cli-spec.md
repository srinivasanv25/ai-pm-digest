# Agent Spec: AI PM Digest

**Status:** v1 built, evaluated and deployed (Cloud Run + Cloud Scheduler).

## Overview
A headless ADK agent that runs once each morning. It gathers the last ~24–72 hours of AI news
aimed at a **PM who builds**, picks the 8–12 items worth their time, explains why each one
matters to a product builder, and emails a short HTML digest (about a 5-minute read) to the
user's Gmail. There is no chat interface in production: a scheduled HTTP call starts the run,
which exits once the email is sent. The ADK web UI can be used to inspect runs (it never sends).

## Language
`python` (ADK Python 2.8, `adk` template, deployment target `cloud_run`).

## Architecture & Sub-Agents
Plain Python handles collection, validation and delivery; the LLM only does judgment and writing.

```
Cloud Scheduler (07:00 America/Los_Angeles)
  └─ POST /digest/send  (OIDC token; Cloud Run service is IAM-private)
       └─ app/daily.py run_daily()
            ├─ once-a-day guard (sent_headlines.json has today's date → skip)
            ├─ SequentialAgent "ai_pm_digest"  (app/agent.py)
            │    before_agent: collect_candidates   Python: RSS → state.feed_items (f1…fN),
            │                                       drops URLs sent in the last 14 days,
            │                                       loads headlines sent in the last 7 days
            │    1. scout_agent      LlmAgent + google_search: ≤5 stories missing from the feeds
            │         after_agent: collect_scout_sources  grounding metadata → state.scout_items
            │                      (s1…sN; follows redirects, reads real page title, drops index pages)
            │         on_model_error: search unavailable → continue feeds-only
            │    2. editor_agent     LlmAgent, output_schema=EditorDigest: picks candidate IDs,
            │                        writes headline / summary / why-it-matters, picks the lead
            │    3. DigestAssembler  BaseAgent (Python): IDs → real URLs, drops unknown IDs,
            │                        dedupes by normalized URL, caps at 12, sets `sendable`
            ├─ render.py      Markdown + email-safe HTML
            ├─ mailer.py      Gmail SMTP (SSL 465, app password); recipient from DIGEST_TO only
            └─ collect.py     record sent URLs + headlines → gs://…/state/ (or ./data locally)
```

**Why the scout is its own agent:** ADK's built-in `google_search` tool can't share an agent
with other tools, and keeping it separate lets the editor work only from saved inputs, never
from its own memory.

**Why IDs instead of URLs:** the editor can only cite `f3` or `s2`. Code resolves those to URLs,
so a hallucinated link is impossible rather than merely unlikely (pattern adapted from the
`deep-search` recipe's `src-N` citations).

### Approaches considered
- **A. Single agent with search + feed tool + send tool.** Fewest files, but the model decides
  when to send email and can cite URLs it invents. Rejected: unsafe and hard to evaluate.
- **B. Python collect → scout + editor agents → Python send (chosen).** Delivery and link
  checking stay deterministic; the LLM does only what it's good at (ranking and writing).
  Easy to evaluate the editor on fixed inputs.
- **C. Adapt `deep-search` wholesale (plan → search → critique loop).** Higher quality ceiling
  but 5–10× the tokens and time per run, and the approval step makes no sense for a daily job.
  Kept as a Future Phase for a weekly "deep dive" edition.

## Digest Sections
1. **Models & lab releases:** new models, pricing and API changes, lab announcements.
2. **Builder tools & launches:** coding agents, frameworks, dev tools, notable launches.
3. **Product & strategy:** AI product teardowns, PM essays, adoption and business moves.
4. **Research worth knowing:** 1–2 papers or ideas in plain language, no math.

Plus a one-paragraph **"If you read one thing"** lead at the top. Empty sections are left out
rather than padded. Each item: headline · source · 1–2 sentence summary · **"Why it matters"**.

## Example Use Cases
- **Normal day:** ~20–60 feed items + a few scout finds → an 8–12 item digest; every item links
  to a real source; email arrives a minute or two after 07:00.
- **Big launch day** (one model release covered by many outlets) → one item citing the lab's
  own post, not near-duplicates.
- **Slow day** (weekend, few good items) → a shorter digest with a note saying so; never padded.
- **Feeds or search partly down** → still sends with what's available; the footer lists what failed.

## Constraints & Safety Rules
- **Recipient is fixed** by `DIGEST_TO`; the LLM never decides who gets email and has no send tool.
- **No invented links:** the editor cites candidate IDs only; unknown IDs are dropped in code.
- **Search results are checked:** the scout's grounding URLs are resolved to the publisher, the
  article's real title is fetched, category/tag/home pages are rejected, and the editor skips
  any result whose claim doesn't match its title.
- **No repeats:** URLs sent in the last 14 days are excluded before the LLM sees them; headlines
  sent in the last 7 days are passed to the scout and editor so the same story from a different
  outlet is skipped.
- **Once a day:** a second trigger on the same (local) day is skipped unless forced; a lock
  rejects concurrent runs.
- **Minimum bar:** fewer than 3 valid items → no email; logged as a warning.
- **Secrets** never live in `.env` (which `agents-cli deploy` copies into the service) and are
  never logged: Secret Manager in production, git- and deploy-ignored `.env.secrets` locally.
- **Private service:** Cloud Run without public access; only the scheduler service account holds
  `roles/run.invoker`.
- Summaries are paraphrased; headlines may not claim more than the source text supports; the
  lead and "why it matters" lines describe what happened rather than forecasting.

## Scheduling & Deployment
Cloud Scheduler job `ai-pm-digest-daily`, `0 7 * * *` America/Los_Angeles, 900s attempt deadline,
2 retries (safe because of the once-a-day guard). Cloud Run: `us-west1`, 2 GiB, 1 vCPU,
min 0 / max 1 instances, 900s timeout. Optional alternative for no-cloud use: macOS launchd
(`scripts/install_schedule.sh`); never run both, since each keeps its own sent history.

## Success Criteria (evaluation) — results
Evaluated on 4 fixed snapshots (`tests/eval/fixtures/`), graded by `tests/eval/grade_local.py`:

| Criterion | Target | Result |
|---|---|---|
| Link grounding (code) | 100% of links from inputs | 4/4 cases pass |
| Fixture expectations (code): count, required/forbidden links, slow-day note | pass | 4/4 cases pass |
| Editorial quality (LLM judge: dedup, relevance, faithfulness, why-it-matters; min of four) | ≥ 4/5 | 5, 5, 4, 5 |
| Held-out case (`busy-day`, never tuned against) | same bar | 1 / 1 / 5 |
| Ops: full run time | < 3 min | ~40–65 s typical (up to ~6 min when Gemini returns 503s and retries) |

## Assumptions
- Email is sent **from and to the user's own Gmail address** (both set in `.env`).
- Delivery at **07:00 Pacific, every day**, weekends included.
- Model: `gemini-3.8-flash` (the scaffold default), used for both scout and editor.
- Two small JSON files are enough memory across days; no Memory Bank needed.
- No feedback or personalization loop in v1.

## Changes from the original spec
- **Scheduling moved from launchd to Cloud Run + Cloud Scheduler** (the original Future Phase 1).
- **Repeats:** dropped the "major update" exception on URLs; added a 7-day headline memory instead,
  because the same story often returns via a different outlet's URL.
- **Search candidates are verified** (real page titles, index pages rejected), after a live run
  showed a grounding claim attached to an unrelated article and a link to a category page.
- **Search is optional:** on a search error the run continues feeds-only rather than failing.
- **Meta AI and One Useful Thing feeds dropped** (stale during the build).
